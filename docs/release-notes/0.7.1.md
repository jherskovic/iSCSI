0.7.0 was not released; its features ship here.

**New**

- Pin a target to a network interface: **Strict** (that interface only) or **Prefer** (fall back to the system's route). Set it in the target editor or in Discover; Sessions shows the interface in use.
- Optional local disk cache per target: off by default, 1–16 GB. Encrypted with a key held only in memory, and discarded when the target is detached.
- Sequential reads reach full speed in about a second instead of ramping up over about 24 seconds.
- 4Kn LUNs partitioned by another initiator now mount instead of showing as unformatted. Blank 4Kn LUNs are presented with 4096-byte blocks, so other 4Kn-aware initiators can read what you format. ([#2](https://github.com/jherskovic/iSCSI/issues/2))

**Setup**

- New step, **Only this copy registered**: finds other registered copies of the app (for example, one run from the disk image) and removes their registrations with **Clean up**. Copies that no longer exist are listed as a note and do not block setup.
- Detects a background service running from another copy of the app and offers **Reinstall**.
- "Approved but not running" can now be fixed with **Reinstall**.
- The filesystem extension is no longer reported as unregistered when macOS's list of extensions omits it but it works; Setup checks with a local test mount.
- A brief FSKit error right after **Enable** no longer offers **Register**, which would have undone it.
- The window no longer freezes while registering the extension.

**Fixes**

- TCP options (Nagle off, keepalive on) are now actually applied; they never took effect before. No measurable throughput change on a LAN.

**Command line**

- `iscsictl --interface <name>` for pinned connections.
- `iscsictl nvme write-bench` for sequential write throughput (destructive).

**Upgrading**

- After the update, Setup asks you to **Reinstall** the background service. On macOS 26, click **Enable** again as well.
